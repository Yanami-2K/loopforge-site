# 场景总览

> **真实场景 · 总览** · 8 个我们自己在用、也推荐你用的场景，全部在一个演示项目里真实跑过。

## 这一章讲什么

演示项目叫「演示 · 发布说明助手」，故事线是：从一句话做出一个"把提交记录整理成发布说明"的小工具开始，到把做法存成团队资产、定时自动跑、再到正式需求走 SOP。

每篇都按同样的顺序写：**能帮你什么 → 怎么说（我们实际发的原话）→ 你会看到什么 → 适合什么时候用**。提示词都很短，因为真实使用时就是这么说的；AI 不清楚的地方会反问你。

| 编号 | 场景 | 你得到的效果 |
| --- | --- | --- |
| **S01** | 一句话让 AI 在云端写个小工具 | 关掉电脑也在跑，回来直接看结果和测试 |
| **S02** | 和同事在同一个会话里接力 | 上下文不丢，接手的人不用重新讲背景 |
| **S03** | 把好用的做法存成团队资产 | 角色、检查清单、SOP，团队里谁都能复用 |
| **S04** | 用 @ 调用团队资产 | 按团队标准检查，结论有依据 |
| **S05** | 定时任务，7×24 小时自动跑 | 到点自动启动，需要人的地方停下来等你 |
| **S06** | 看用量和交付 | 花了多少、交付了多少，一页看清 |
| **S07** | 在本地 IDE 里用平台 | 不开网页也能查进度、派任务 |
| **S08** | 对话里理清需求，交给 SOP 跑完 | 自动建需求单，侧边栏实时看每一步 |

## 两种工作方式

* **直接对话**：探索、写小工具、快速修改。对应 S01–S04。
* **交给 SOP**：正式需求，要固定的评审、测试和人工把关。对应 S05、S08。

两种方式在同一个项目里，可以先聊清楚，再交给 SOP。

> **在你自己的部署里**：先完成 [配置模型 API Key](../01-getting-started/06-configure-api-key.md)。截图里的名字来自演示项目，你的项目里一开始没有；按 S01 → S03 的顺序做，会得到同样的工具和资产。
